## Part 1 — fact verification results

### Where fable was right and v2.2 was wrong (the big one)

**Org-level "require workflows to pass before merging" IS available on GitHub Team plans.**
v2.2 said Enterprise-only, based on the rule rendering only in the enterprise-cloud docs
version. The round-4 researcher traced the mechanism: the docs section is gated by feature
flag `repo-rules-required-workflows.yml`, committed once in 2023 (when org rulesets themselves
were Enterprise-only) and never updated. Meanwhile: the 2025-06-16 changelog explicitly lists
"requiring GitHub Actions workflows" among Team-plan capabilities; the Team-enablement docs PR
(github/docs 3eb3f989) enumerated five explicit Team carve-outs and required-workflows was not
one of them; the free-pro-team REST reference documents the org `workflows` rule type in full;
and the roadmap item's SKU label is "All". One mechanism (stale docs flag) explains every
observation, including why v2.2's method — doc-version presence — misfired. Residual honesty:
this is documentary; the settling experiment (create a disabled org ruleset with a workflows
rule; 201 = available, 422 = gated) needs the owner's org credential and authorization.

**Lesson institutionalized as prime directive 7 in v2.3: host facts are probed, never
hardcoded.** The spec's own host calibration went stale between drafts — exactly the failure
class sisu exists to catch, caught in sisu's own spec by the process building it.

## Part 2 — design review adjudication (11 prescriptions)

1. **Uneven-depth v1 + kill criteria — ADOPT-TRIMMED.** Premise half-wrong: the ledger and the
   knowledge engine's behavior list are ALREADY as thin as prescribed; the real additions are
   (a) pre-committed kill criteria and (b) doctor health rows. Reconciliation ruled: a
   pre-committed exit is not a deferral — same idiom as waiver expiry. Depth floor stays set by
   DoD #5's knowledge rows; "shallow" may not drop any of them.
2. **`detected:` namespace in the intent file — ADOPT-TRIMMED.** Called "the sharpest finding
   in the review": v2.2 put detection findings in a hand-editable file with no provenance —
   the 1506-vs-1502 defect reproduced inside sisu's own control file. Trim: "stamp with the
   commit" is unimplementable at init (the commit doesn't exist yet) — stamp with HEAD-at-
   detection + a disclosed-partial digest of detection inputs.
3. **Canonical granularity (small files, compose at emit, override at source grain) — ADOPT.**
   The reference corroborates both directions: its monolithic root file's hand-written roster
   drifted; its per-file agents layer was machine-checkable and got pinned.
4. **Emitter purity — ADOPT.** v2.2 asserted purity of the resolver but never of emitters; one
   `claude --version` peek voids byte-reproducibility. Target knowledge becomes committed
   constants keyed by contract version. Oracle already exists (DoD byte-repro test).
5. **Catalog lifecycle — ADOPT-TRIMMED.** Schema version only (content ships with the
   generator — otherwise it contradicts #7); ids never reused; deprecated still renders
   ("omission is permitted; silence is not" applied to the catalog itself); lifecycle is
   orthogonal to the enforcement tuple.
6. **Doctor JSON contract + CI boundary — ADOPT-TRIMMED.** JSON schema day one; volatile fields
   segregated. Trim HARD on "doctor --local-only is CI-safe": doctor is never emitted into a
   consuming repo's jobs (directive 1 would die); `--format=json` is for sisu's own CI and
   human diffing; downstream posture-in-CI = probe specs rendered into the Component-11 suite.
7. **Version axes → 3 — ADOPT.** (Premise slightly overstated — v2.2 had four axes, not five —
   which strengthens the collapse.) Manifest still records pack content hashes as audit data.
8. **Ledger CI-pointer — ADOPT.** "Best cost/value in the review." Conditions: the pointer is
   agent-written, so it is `self-attested` until doctor --remote resolves it, `unknown` when
   hostless, and never rendered as the CI verdict itself.
9. **Role dispatch — ADOPT, strengthened.** The reference's root file carries exactly such a
   section, with the stated compaction-survival reason, and its worst incident is the proof.
   Strengthened beyond the reviewer: the map must be GENERATED from the canonical role set
   (the reference's hand-written roster was incomplete while every listed entry resolved), and
   the self-verification check is BIDIRECTIONAL (targets resolve AND every non-omitted role
   appears). Capture helper: adopt — it is the missing instance of an existing rule.
10. **Sequencing — ADOPT-TRIMMED.** Skeletal upgrade early (it carries the granularity
    constraint); byte-repro in the thin slice ("highest-value item in the whole review") but
    only across the DECLARED OS set; cold-agent smoke early with DoD #2 unchanged as the final
    gate; canonical-tree lint in sisu's own CI (labeled detective). Dogfood adopted with two
    guards the reviewer omitted: pin sisu's own harness to a RELEASED generator (a bug in HEAD
    must not disarm the gates that would catch it), and dogfood never counts toward DoD #2
    (sisu's own stack is the one most at risk of being mistaken for mechanism).
11. **Economics — ADOPT-TRIMMED.** Pairwise matrix adopted with two full-coverage carve-outs
    (per-target --strict, per-profile omission rendering — those rows make per-axis claims).
    Fleet-drift-out-of-scope adopted verbatim. **REJECTED: the 30-second waiver flow** — it
    conflates the agent-effort clock (capture, voluntary compliance) with the human-approval
    clock (the ratchet's single legal loosening); a frictionless approval on a same-principal
    setup converts the ratchet into a suggestion. Adopted only its mechanics: scaffolded waiver
    file, prefilled identity/expiry, doctor days-remaining. What catches routing-around is the
    measurement-identity guard, which fires regardless.
